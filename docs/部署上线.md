# Ubuntu + 宝塔部署

第一版不强制容器化。服务器是阿里云 Ubuntu、宝塔管理、Java 以 JAR 运行时，可以将 Python Worker 作为独立的 `venv + uvicorn + Supervisor` 进程部署；后续需要 Playwright 浏览器时再增加 Chromium 和 Xvfb。

## 0. Java Manager 使用 JAR 启动

Java Manager 由 `sf-manager-xstarter` 生成可执行 JAR，生产运行直接由宝塔 Supervisor 或 systemd 管理 JAR 进程，不使用 Maven 常驻运行。示例：

```bash
mkdir -p /opt/id-game-distribution-manager
cp sf-manager-xstarter-1.0.0.jar /opt/id-game-distribution-manager/
cd /opt/id-game-distribution-manager
exec /usr/bin/java -Xms512m -Xmx2048m -jar sf-manager-xstarter-1.0.0.jar
```

Java Manager 启动后，先确认它实际监听的端口和回调地址，例如：

```bash
curl -i http://127.0.0.1:8080/actuator/health
```

Python 的 `JAVA_CALLBACK_BASE_URL` 必须指向同一个 JAR 服务的内网地址，并保留 `/internal/creative/runs` 路径：

```dotenv
JAVA_CALLBACK_BASE_URL=http://127.0.0.1:8080/internal/creative/runs
```

如果 Java JAR 和 Python Worker 不在同一台服务器，把 `127.0.0.1` 改成 Java 服务器内网 IP，并只在阿里云安全组中放行 Python 服务器 IP。Java JAR 和 Python Worker 启动后，再从 Python 提交 Mock 或真实网页任务验证回调入库。

## 1. 目录和账号

建议使用独立账号和目录：

```bash
sudo useradd --system --create-home --shell /usr/sbin/nologin gameworker
sudo mkdir -p /opt/id-game-distribution-python-workers/{current,shared/logs,shared/profiles,shared/evidence}
sudo chown -R gameworker:gameworker /opt/id-game-distribution-python-workers
```

代码从 Git 仓库拉到 `current`，配置写入 `/opt/id-game-distribution-python-workers/shared/.env`，不要提交 `.env`、浏览器 Profile 或 Cookie。

## 2. 安装和启动

```bash
cd /opt/id-game-distribution-python-workers/current
python3 -m venv .venv
. .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
cp .env.example /opt/id-game-distribution-python-workers/shared/.env
```

把 `.env` 的 `JAVA_CALLBACK_BASE_URL` 指向 Java Manager 的内网地址，例如 `http://127.0.0.1:8080/internal/creative/runs`。运行命令：

```bash
set -a; . /opt/id-game-distribution-python-workers/shared/.env; set +a
exec /opt/id-game-distribution-python-workers/current/.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8091 --workers 1
```

### 代理配置

建议为不同平台/地区准备稳定的逻辑 Profile。真实地址只写在服务器 `.env`：

```dotenv
PROXY_PROFILE_GOOGLE_HK=socks5://username:password@proxy.example.com:1080
PROXY_PROFILE_META_DEFAULT=http://username:password@proxy.example.com:8080
```

Java Quartz 只传 `proxyProfile` 和 `proxyRequired`，不要把带账号密码的代理 URL 传进 Java、数据库或日志。Google 浏览器要让同一个持久化 Profile 长时间使用同一地区出口，频繁换 IP 会增加登录验证和验证码概率。代理供应商必须允许目标平台访问，并确认其服务条款、地区出口和带宽。

Manager 回调方法使用 `@NoNeedLogin` 和 `@NoNeedCheckHeader` 放行，因此回调地址必须只监听本机/内网，并通过阿里云安全组或 Nginx 访问控制限制来源；不要把此内部接口暴露到公网。

任务状态保存在进程内存中，因此第一版必须单进程运行；Java 的 `creative_run` 才是最终持久化记录。重启后未完成的内存任务需要由 Java 按运行记录重试。

## 3. 宝塔 Supervisor

在宝塔安装 Supervisor 后新增程序：

```text
名称：id-game-distribution-python-workers
运行用户：gameworker
启动目录：/opt/id-game-distribution-python-workers/current
启动命令：/opt/id-game-distribution-python-workers/current/.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8091 --workers 1
自启动：是
自动重启：是
标准输出日志：/opt/id-game-distribution-python-workers/shared/logs/worker.log
错误日志：/opt/id-game-distribution-python-workers/shared/logs/worker-error.log
```

如果不使用宝塔，也可以使用 systemd；不要同时用 Supervisor 和 systemd 管理同一个进程。

## 4. Playwright 浏览器（Google Worker 开启时）

```bash
sudo apt-get update
sudo apt-get install -y xvfb
. /opt/id-game-distribution-python-workers/current/.venv/bin/activate
pip install playwright
playwright install --with-deps chromium
```

浏览器 Worker 不需要把 Chrome 暴露到公网。无界面采集可直接使用 Playwright headless；需要人工登录或处理验证码时，用虚拟显示器启动：

```text
启动命令：xvfb-run -a --server-args="-screen 0 1920x1080x24" /opt/id-game-distribution-python-workers/current/.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8091 --workers 1
```

程序内用 `launch_persistent_context` 指向共享 Profile，并在 BrowserContext 级别设置 `proxy`。同一 Profile 不要在不同国家代理之间切换。首次初始化时允许人工看到浏览器窗口；初始化完成后恢复为后台运行。

使用独立 Profile：`/opt/id-game-distribution-python-workers/shared/profiles/google-transparency`。首次运行由人工登录并处理验证码，Profile 目录权限只给 `gameworker`，不进入 Git 和日志。浏览器遇到登录过期、验证码或页面变更时必须回调 `WAITING_MANUAL`。

## 5. 发布、检查和回滚

发布步骤：

1. 在 Git 仓库提交代码并打版本标签。
2. 服务器拉取新版本到新的发布目录。
3. 安装依赖并执行测试。
4. Supervisor 停止旧进程，切换 `current`，再启动。
5. 访问 `http://127.0.0.1:8091/health`，从 Java 机器提交一个 Mock 或灰度任务。

回滚时切回上一个已验证目录，保留 `shared` 下的 `.env`、Profile、日志和证据。发布前不删除旧目录，确认健康检查和 Java 回调成功后再清理。

## 6. 网络边界

Python 端口只监听 `127.0.0.1` 或服务器内网地址，不在宝塔开放公网端口。若 Java 和 Python 不在同机，使用阿里云安全组限制内网源 IP。回调接口不使用登录和自定义 Header 校验，因此网络边界必须配置正确。

代理只用于 Python Worker 到第三方平台的出站连接，不能替代 Java/Python 内网安全控制。上线前应分别验证：`curl` 或 Playwright 访问目标站点的出口 IP、代理认证、DNS 解析、TLS、超时和断线重连；不要只验证代理端口能连通。
