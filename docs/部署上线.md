# 宝塔 Python 项目部署与管理

本文按提供的宝塔截图编写，入口是 **网站 → Python 项目 → Python 环境管理 / 添加项目**。由这个面板统一管理 Python Worker 的启动、停止、重启和日志，不再为同一服务另外配置 Supervisor、systemd 或 `nohup`。

项目入口为 `python -m app --env-file .env.production`（对应 `app/__main__.py`），内部启动单进程 Uvicorn。以下为配置指南，尚未在目标宝塔服务器执行；截图没有展示的自动重启、日志位置等设置，需要在创建后的项目详情中核实。

## 0. 是否需要打包，上传哪些文件

**不需要编译成 JAR、EXE 或 wheel。** 这是直接运行源码的 Python 服务，可以通过宝塔文件管理上传目录，也可以先压缩为 ZIP 后上传解压；ZIP 只是传输方式，不是必需的构建步骤。服务器仍需安装独立 Python 环境、依赖包和 Chromium。

最少上传：

```text
app/                       # 全部 Python 源文件，保留包目录结构
requirements.txt
.env.production.example    # 不含真实密码的生产配置模板
```

`README.md`、`docs/` 可一起上传便于查阅；`scripts/`、`tests/` 可按维护需要上传。排除 `.git/`、`.idea/`、`.venv/`、`__pycache__/`、`.pytest_cache/`、本地 `.env*` 实际配置、`data/`、`evidence/`、`profiles/`、`logs/`。`.env.example` 和 `.env.production.example` 是模板，可以上传。不要把 Windows 虚拟环境复制到 Linux，也不要用本地 SQLite 覆盖服务器数据。

首次发布：上传源码 → 安装服务器依赖和 Chromium → 将生产模板复制为 `.env.production` 并核对 → 在宝塔按生产命令启动。后续发布只更新代码和所需依赖，保留服务器实际配置与 `shared` 数据。

## 1. 先准备 Python 环境（对应截图 1、2）

截图中的环境列表：

| 截图选项 | 本项目如何选择 |
| --- | --- |
| `pyenv` / Python 3.7.16 / 宝塔面板环境 | **不选，也不要升级、卸载或修改它**。这是面板自身环境，本项目代码使用 Python 3.10+ 语法 |
| Python 3.14.4 / 系统级环境 | 截图可见，但本项目尚未验证这套版本及其依赖兼容性，不作为默认部署环境 |
| 新建项目独立虚拟环境 | **推荐基于 Python 3.12 创建**，命名为 `game-workers`，只给本项目使用 |

在「Python 环境管理」中：

1. 打开「版本管理」，查看是否可安装 Python 3.12，并完成安装；也可使用 Python 3.11。
2. 点击「创建虚拟环境」，选择上述版本，建立 `game-workers`。不要把依赖装进宝塔自己的 `pyenv`。
3. 查看该环境的「解释器位置」，记录 **Python 可执行文件的绝对路径**，应具体到 `bin/python`，不只是环境目录。
4. 如果面板版本管理不提供所需版本，可先单独安装兼容解释器，再通过「添加」登记；不替换宝塔自身环境或系统 Python 链接。

截图未展示创建虚拟环境的完整表单，环境存放路径以面板实际生成结果为准。本文命令里的 `WORKER_PY` 必须替换为它的真实解释器路径。

**顶部「命令行版本」与添加项目时的「Python 环境」分别设置。** 不要认为修改顶部下拉框就已经给项目选好了环境。以下维护命令使用解释器绝对路径，不依赖顶部的「系统默认」或裸 `pip` 指向哪个环境。

## 2. 上传代码并准备持久数据目录

沿用本项目原部署约定目录，宝塔的项目路径可以选择 `/opt`，不要求一定放在 `/www/wwwroot`：

```text
/opt/id-game-distribution-python-workers/
├── current/                 # 代码根目录，也就是面板中的「项目路径」
│   ├── app/
│   ├── requirements.txt
│   ├── .env.production.example
│   └── .env.production                 # 服务器配置，发布时保留
└── shared/
    ├── data/                # SQLite，更新代码不删除
    └── browsers/            # Playwright Chromium
```

在宝塔「文件」中创建目录并上传 / 解压代码，或在面板终端从 Git 拉取代码。确保 `current` 下直接包含 `app/` 和 `requirements.txt`，没有多套一层仓库目录。

不上传 Windows 的 `.venv`、`.idea`、本地 `.env` / `.env.production` 和测试 `data/worker.db`。Python 虚拟环境使用第 1 节创建的服务器环境。

本指南按截图默认的 **启动用户 `www`** 编写。在宝塔终端以具有 sudo 权限的账号准备目录：

```bash
sudo mkdir -p /opt/id-game-distribution-python-workers/current
sudo mkdir -p /opt/id-game-distribution-python-workers/shared/{data,browsers}
sudo chown -R www:www /opt/id-game-distribution-python-workers/shared
```

通过宝塔文件权限设置，确保 `www` 能遍历项目父目录、读取代码、执行虚拟环境的 Python，并能写入 `shared/data` 和 `shared/browsers`。不要用 `chmod 777` 解决权限问题。若改用独立账号 `gameworker`，面板启动用户、目录权限及后文 `sudo -u www` 必须一起调整。

如果已有线上实例，沿用其数据和配置路径；不要因为本文示例而新建空库替换已有数据。原来使用 `shared/.env` 加 `current/.env` 软链接的部署可以继续使用旧启动命令 `python -m app`；切换到新命令时，先将已核对的生产配置保存为 `.env.production`，也可以让该文件链接到共享配置，确保 `www` 能读取目标。不要用模板覆盖旧配置中的真实值。

## 3. 配置服务器 .env.production

首次部署，在宝塔文件管理中将 `current/.env.production.example` 复制为 `current/.env.production`，再编辑内容。已有 `.env.production` 时只修改需要的字段，不覆盖整个文件。

本地仍使用 `.env` 和 `python -m app`。生产指定 `--env-file .env.production`；文件不存在或路径是目录时启动会报错，不会回退读取 `.env`。文件相对路径按工作目录解析，也可指定绝对路径，例如 `--env-file /opt/id-game-distribution-python-workers/shared/.env.production`。实际 `.env.production` 已被 Git 忽略，模板可提交。

可以在宝塔文件管理中复制模板，或在项目根目录执行以下命令（已有配置时保留）：

```bash
cd /opt/id-game-distribution-python-workers/current
if [ ! -e .env.production ]; then
  cp .env.production.example .env.production
fi
```

模板使用现有 Java 生产回调域名；发布前确认域名和 `DATABASE_PATH` / `PLAYWRIGHT_BROWSERS_PATH` 与目标服务器一致。


```dotenv
APP_NAME=id-game-distribution-python-workers
APP_ENV=production
HOST=127.0.0.1
PORT=13371
JAVA_CALLBACK_BASE_URL=https://api-manager.mar2game.com/internal/creative/runs
CALLBACK_TIMEOUT_SECONDS=10
JOB_TIMEOUT_SECONDS=900
MAX_CONCURRENT_JOBS=2
DATABASE_PATH=/opt/id-game-distribution-python-workers/shared/data/worker.db
PLAYWRIGHT_BROWSERS_PATH=/opt/id-game-distribution-python-workers/shared/browsers
PROXY_DEFAULT_URL=
```

只让运行用户和管理员读取配置。例如，普通 `.env.production` 文件可在终端设置：

```bash
sudo chown www:www /opt/id-game-distribution-python-workers/current/.env.production
sudo chmod 600 /opt/id-game-distribution-python-workers/current/.env.production
```

- `python -m app --env-file .env.production` 只加载指定文件，不合并本地 `.env`，面板的「环境变量」可以选 **无**。不要同时在多处填写相同变量；系统 / 面板注入的环境变量优先于 `.env.production`。
- `DATABASE_PATH` 指向代码目录外的共享数据，避免发布覆盖数据。已有数据库需要迁移时，先停止旧实例、备份完整数据库，再迁移，不能只改路径。
- 只启动 Python API / Mock，不需要 Java、MySQL、Redis。只有回调 Java 主库时才需要 Manager。
- 当前 Quartz 固定调用本机 `http://127.0.0.1:13371`，因此 **Worker 与 Quartz 同机部署**。任务自带的 `callbackUrl` 优先于 `.env.production`；Quartz 开发回调本机 `13367`，生产回调 `https://api-manager.mar2game.com/internal/creative/runs/{runID}/callback`。跨机或改端口需要同步调整 Java 地址来源，不是只修改 Python `.env.production`。
- `MAX_CONCURRENT_JOBS=2` 是单进程内任务并发上限，不是启动两个服务进程。

需要代理时，在同一 `.env.production` 中补充实际值：

```dotenv
PROXY_PROFILE_GOOGLE_HK=socks5://username:password@proxy.example.com:1080
PROXY_PROFILE_META_DEFAULT=http://username:password@proxy.example.com:8080
```

Python API 支持在任务顶层传逻辑 `proxyProfile` 和 `proxyRequired`，这里的 Profile 不是浏览器登录 Profile。**当前 Quartz 派发尚未传这两个字段**；Python 在未指定 Profile 且不要求代理时直接直连，所以只设置 `PROXY_DEFAULT_URL` 不会让现有 Java 任务自动使用代理。需要代理的部署必须先完成 Java 参数贯通或用显式传参的任务验证；带认证代理也需单独检查当前 Worker 的浏览器连接兼容性。不要将真实代理密码提交到仓库或贴到日志中。

## 4. 添加 Python 项目（对应截图 3、4）

回到「Python 项目」，点击 **添加项目**，逐项填写：

| 面板字段 | 填写值 / 操作 |
| --- | --- |
| 项目名称 | `id-game-distribution-python-workers` |
| Python 环境 | 第 1 节创建的独立环境 `game-workers`，确认版本为 Python 3.12 或 3.11 |
| 启动方式 | **命令行启动** |
| 项目路径 | `/opt/id-game-distribution-python-workers/current` |
| 启动命令 | `python -m app --env-file .env.production`；推荐将 `python` 替换为所选环境的真实解释器绝对路径，见下文 |
| 环境变量 | **无**；入口会读取项目 `.env.production` |
| 启动用户 | **www**，与目录权限及浏览器安装用户一致 |
| 安装依赖包 | 选择文件 `/opt/id-game-distribution-python-workers/current/requirements.txt`，不是目录，也不是安装命令 |
| 更多设置 → 项目初始化命令 | **留空**；不需要 Django 的 `makemigrations` / `migrate` |

启动命令完整形式如下，必须将占位路径替换为环境管理中看到的真实路径，不能原样复制占位内容：

```text
/所选虚拟环境的实际路径/bin/python -m app --env-file .env.production
```

此处不填写 `WORKER_PY` 变量，因为面板启动进程不会继承你在另一个终端临时定义的变量。也不需要在命令里加 `&`、`nohup` 或后台激活虚拟环境。

截图底部对「执行命令」的提示没有展示最终生成的进程命令，因此保存后需核对项目配置 / 启动日志：**最终应只调用一次所选解释器，并带参数 `-m app --env-file .env.production`**。如果该面板版本会自动在输入内容前加解释器，参数框改填 `-m app --env-file .env.production`，避免生成 `python python -m app --env-file .env.production`。以创建后的实际命令为准。

本项目是 FastAPI / ASGI，当前入口已经负责启动 Uvicorn，因此选「命令行启动」，无需选择 `uwsgi` 或配置 `gunicorn`。不要填 `app/main.py`、单独的 Worker 文件或仅填 `app.main:app`。

点击「确定」，查看依赖安装结果和项目状态。若面板创建时会自动生成另一套项目虚拟环境，应以**项目最终使用的解释器**为准，重新记录路径；后续安装、测试和启动必须用同一个环境。

截图没有展示开机启动、异常重启、进程数量或日志路径的配置：创建后在项目详情中核实，支持时开启开机启动和异常自动重启，进程数量设为 `1`。**不要加 `--reload` 或多 workers**，实时任务队列保存在进程内存中。

## 5. 在宝塔终端安装 Chromium

### 5.1 截图中的 chromium（Docker应用）是否需要安装

**不需要安装软件商店里的 `chromium（Docker应用）`。** 截图展示的是独立 Docker 应用；本项目部署在宝塔 Python 虚拟环境中，需要用该环境的 Playwright 安装配套浏览器。

两个 Worker 当前都调用 `playwright.chromium.launch(headless=True)`，由 Python 在本机启动浏览器，没有连接 Docker 浏览器的远程接口。安装软件商店的 Chromium 不会自动让本项目找到它，也不能替代下面的 Playwright 安装命令。

| 组件 | 本项目的安装方式 |
| --- | --- |
| Python 的 Playwright 包 | 在项目环境中安装 `requirements.txt`，文件已包含 `playwright` |
| 浏览器运行所需的 Linux 系统库 | 在宝塔终端执行 `python -m playwright install-deps chromium`，需要管理员权限 |
| 与 Playwright 配套的 Chromium | 在宝塔终端执行 `python -m playwright install chromium`，按下文指定运行用户和浏览器目录 |
| 软件商店的 chromium（Docker应用） | 当前部署流程不使用 |

操作入口是截图左侧的 **「终端」**，不是软件商店的「安装」按钮。先到 **网站 → Python 项目 → Python 环境管理** 确认本项目实际解释器路径，再按下面命令安装。若已经安装过 Docker Chromium，不必为本项目再次安装或配置它；是否保留由其他用途决定。

### 5.2 确认项目环境并安装浏览器

安装 `requirements.txt` 只安装 Python 包，不会安装浏览器。两个真实 Worker（Meta / Google）都需要 Chromium；没有浏览器时 API 可能仍然健康，但抓取任务会失败。

打开宝塔终端，先将以下第一行替换为第 4 节确认的项目解释器路径，再执行。以后重新打开终端也需要重新设置 `WORKER_PY`：

```bash
WORKER_PY='/所选虚拟环境的实际路径/bin/python'
"$WORKER_PY" --version
"$WORKER_PY" -c 'import sys; print(sys.executable)'
"$WORKER_PY" -m pip --version
"$WORKER_PY" -m pip show fastapi uvicorn python-dotenv playwright
```

如面板依赖安装失败，先查看面板安装日志，修复原因后通过面板重试。也可由拥有该虚拟环境写权限的维护账号执行：

```bash
"$WORKER_PY" -m pip install -r /opt/id-game-distribution-python-workers/current/requirements.txt
```

在 Ubuntu 上以管理员权限安装浏览器系统依赖，再以实际运行用户 `www` 下载浏览器：

```bash
sudo "$WORKER_PY" -m playwright install-deps chromium
sudo -u www env PLAYWRIGHT_BROWSERS_PATH=/opt/id-game-distribution-python-workers/shared/browsers "$WORKER_PY" -m playwright install chromium
```

Playwright 安装命令不自动读取 `.env.production`，因此这里显式传入 `PLAYWRIGHT_BROWSERS_PATH`；服务启动时则从 `.env.production` 读取相同路径。这样不会把浏览器装进 root 的缓存目录导致 `www` 找不到。

### 5.3 验证浏览器可用

可在正式提交抓取任务前验证运行用户能启动 Chromium，此检查不访问外部网页：

```bash
sudo -u www env PLAYWRIGHT_BROWSERS_PATH=/opt/id-game-distribution-python-workers/shared/browsers "$WORKER_PY" - <<'PY'
from playwright.sync_api import sync_playwright
with sync_playwright() as p:
    browser = p.chromium.launch(headless=True)
    print("Chromium OK:", browser.version)
    browser.close()
PY
```

输出 `Chromium OK: ...` 且进程正常退出，说明该运行用户能找到并启动浏览器；这仍不代表已验证外部平台访问。升级 Playwright 包后，重新执行浏览器安装及此检查，保持版本匹配。

安装完成后回到 **Python 项目列表** 启动 / 重启项目。当前代码使用 `chromium.launch(headless=True)`，无需 Xvfb；持久化浏览器登录和可视化人工接管尚未实现，不能靠安装 Xvfb 自动获得这些能力。

## 6. 检查项目是否部署成功

### 6.1 面板状态、API 和日志

在项目列表确认运行状态，通过创建后的项目详情查看运行日志 / 错误日志（入口名称和日志路径以该版本实际界面为准）。正常日志通常包含 Uvicorn 监听地址 `http://127.0.0.1:13371`。正常启动日志也可能写入 stderr，不能仅凭错误日志有内容判断失败。

在**服务器的宝塔终端**执行：

```bash
curl --fail --show-error http://127.0.0.1:13371/health
curl --fail --show-error http://127.0.0.1:13371/workers
```

预期健康检查含 `"status":"UP"`、`"environment":"production"`；Worker 列表含 `mock`、`meta_library`、`google_transparency`。这里的 `127.0.0.1` 指服务器，不能直接在自己电脑浏览器里用这个地址访问服务器。

### 6.2 先做不回调 Java 的 Mock 检查

```bash
curl --fail --show-error -X POST http://127.0.0.1:13371/jobs \
  -H 'Content-Type: application/json' \
  -d '{"worker":"mock","payload":{"items":[{"externalAdID":"deploy-check-1","copyText":"deployment check"}]}}'
```

复制返回的 `jobID`，替换下面占位内容后查询：

```bash
curl --fail --show-error http://127.0.0.1:13371/jobs/返回的jobID
```

等待状态变为 `SUCCESS`，确认 `shared/data/worker.db` 已创建。这个示例没有 `runID` / `callbackUrl`，不会回调 Java，但会写入一条测试任务和素材记录。

### 6.3 再验证 Java 回调及真实抓取

Java Manager 和 Quartz 是独立 JAR 服务，可在宝塔 Java 项目中管理；不在 Python 初始化命令中启动 Java。完整 CMS 链路需要两者，Quartz 与 Worker 同机，Manager 可按现有 Java 生产部署运行。生产 `env=pro` 时 Quartz 显式下发 Manager HTTPS 域名回调，开发才是本机 `13367`；`.env.production` 的回调基础地址仅作为手工提交等未指定 callbackUrl 的默认值。

先确认 Manager 与 Quartz 服务存活；同机且启用了 Actuator 时，可用 `curl -i http://127.0.0.1:13367/actuator/health` 辅助检查 Manager，其他部署地址按实际环境调整。再从 CMS 触发，由 Quartz 创建运行记录并提交 Worker，确认回调和业务入库。当前立即抓取会扫描全部启用配置，灰度前先确认范围。步骤见[本地验收](本地验收.md)，生产使用实际业务配置，不套用示例 ID。

最后执行一次小规模 Meta / Google 抓取，确认 Chromium、代理出口和第三方页面可用。`/health` 成功不代表这些依赖或 Java 回调成功。出现 `WAITING_MANUAL` 时按错误信息排查验证 / 登录限制。

## 7. 后续通过面板更新、启停和回滚

| 操作 | 在面板中的处理 |
| --- | --- |
| 启动 / 停止 / 重启 | 使用 Python 项目列表或项目详情中的对应操作，以实际界面名称为准 |
| 修改配置 | 文件管理编辑 `current/.env.production`，然后重启项目 |
| 查看异常 | 查看项目运行 / 错误日志，再查询具体 `jobID`；不要仅看列表“运行中” |
| 修改依赖 | 停止服务后，用项目实际解释器安装新的 `requirements.txt`；Playwright 升级后重新安装 Chromium |
| 更换解释器 | 在环境管理准备新环境，给项目切换后重新安装依赖与浏览器，核对实际启动命令 |

推荐发布顺序：

1. 在本地完成测试，记录发布的 Git 提交或版本，保留本次和上次的依赖版本清单；`requirements.txt` 使用版本范围，重新安装不保证得到原来完全相同的依赖。
2. 等待运行中任务完成，在面板**停止** Python 项目。重启会丢失实时任务队列，未完成任务不会自动恢复，需要 Java 按业务运行记录重试。
3. 在宝塔文件管理备份现有代码、`.env.production` 和停止后的共享数据库。更新 `current` 中代码文件，保留服务器 `.env.production`、共享数据和面板管理的虚拟环境；删除旧代码文件应按版本差异处理，避免残留。
4. 依赖有变化时，在面板安装或用同一解释器执行 `-m pip install -r requirements.txt`；Playwright 有变化时执行第 5 节。可用 `"$WORKER_PY" -m pip freeze` 留存部署依赖清单。
5. 回到面板启动项目，依次验证健康检查、Mock、Java 回调和小规模真实抓取，确认日志正常。

回滚时先在面板停止服务，恢复上一个已验证代码版本及匹配的依赖环境，再启动并检查。保留 `.env.production` 和业务数据；若新版改动了数据库结构，应先确认旧版兼容性，不直接用旧备份覆盖上线后新产生的数据。

## 8. 常见问题与网络设置

| 现象 | 优先检查 |
| --- | --- |
| Python 语法错误 / 依赖版本不支持 | 是否误选截图中的 `pyenv` 3.7.16，核对项目实际解释器 |
| 缺少 `uvicorn` / `fastapi` / `dotenv` | 依赖是否安装到了项目实际使用的环境；不要只在系统环境里执行 `pip install` |
| `No module named 'app'` | 项目路径是否为含 `app/` 的代码根目录，有无多套一层目录 |
| `can't open file ... python` 或重复解释器 | 检查面板生成的实际命令，是否变成 `python python -m app --env-file .env.production` |
| 相对导入报错 | 是否直接运行了 `app/main.py`，应使用模块 `app` |
| `Permission denied` / `unable to open database file` | `www` 是否能访问代码和解释器，并写入共享数据目录 |
| Playwright 提示 executable 不存在 | 浏览器安装与运行的 `PLAYWRIGHT_BROWSERS_PATH`、用户及 Playwright 版本是否一致 |
| `Address already in use` | 是否遗留了终端启动、Supervisor 或其他实例；同一服务只由 Python 项目面板管理 |
| 修改 `.env.production` 不生效 | 是否重启；面板环境变量是否覆盖了文件值；软链接是否指向预期文件 |
| `CALLBACK_FAILED` | Java 是否启动、回调地址 / runID 是否有效、网络和 Java 日志是否正常 |
| 重启后旧 `jobID` 返回 404 | 当前任务查询来自内存，不会从 SQLite 自动恢复；审计记录仍可保留 |

Worker 与 Quartz 同机时保持 `HOST=127.0.0.1`，无需为 Worker 绑定公网域名、配置公网反向代理或放行 `13371`。当前 Java 生产回调使用 Manager HTTPS 域名，应核实该回调路径的来源限制；回调注解不校验登录或自定义 Header，不能假设已经由网络隔离。若以后改变 Worker 部署拓扑，应同步修改 Java 目标地址并实施访问控制。
