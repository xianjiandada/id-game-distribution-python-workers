# 开发计划

## 已完成的基础版本

- Worker 注册表和统一任务 API。
- Mock Worker，可验证成功、失败和结果条目。
- Meta 和 Google Worker 的安全占位状态。
- 异步任务、并发上限、超时和 Java 回调客户端。
- API、回调、失败和未知 Worker 的本地测试。
- Meta Ads Library 公开网页抓取：按关键词、国家、状态和媒体类型加载结果卡片。
- Google Ads Transparency 公开网页搜索：按广告主名称定位广告主并提取素材 ID、版本和详情 URL。

## 本地真实网页烟测结果（2026-10-26）

- Meta：`keyword=game`、`country=HK`，Playwright 加载到广告结果，单次提取 3 条素材；页面 HTTP 状态为 403，但页面仍渲染了结果卡片，因此实现按“是否有结果卡片”判断成功，不能只按 HTTP 状态判断。
- Google：`advertiserName=supercell`、`region=HK`，搜索到 `Supercell Oy`，进入广告主详情页后提取到 3 条素材，包含 `advertiserID`、`creativeId`、`versionId` 和详情 URL。
- 指定样例：Facebook `螺丝` + `country=ALL` 页面显示约 260 条结果，本次提取前 5 条；Google `SOFISH TECHNOLOGY PTE. LTD.` + `region=SG` 页面显示约 412 条广告，本次提取前 5 条。
- 替代查询：Meta `手机壳` 抓取 2 条、Google `Supercell Oy` + `region=HK` 抓取 2 条；Meta `游戏` 抓取 1 条、Google `Playrix` + `region=HK` 抓取 1 条，均未登录且返回 `SUCCESS`。
- 替代查询统一使用 `python scripts/live_smoke_test.py --meta-keyword "手机壳" --google-advertiser "Supercell Oy" --google-region HK`，便于小规模复验其他关键词和竞品公司。
- 两个平台都没有调用 Graph API、Google Ads API 或附件中的 access token。
- 测试截图保存在本地 `evidence/`，该目录已加入 `.gitignore`，不会提交浏览器页面内容。

## 下一阶段：Java Manager 接入

1. 在 `sf-manager-web` 增加内部回调 Controller。
2. 在 `sf-manager` 增加回调 Service，校验 `runID` 和回调状态。
3. 增加 `advert_creative_run`、`advert_creative_item` 的持久化和唯一键。
4. Quartz 创建运行记录后调用 Python `/jobs`，收到 202 后立即结束当前调度线程。
5. 回调到达后更新运行状态，重复回调只返回成功，不重复入库。

## 再下一阶段：真实 Worker

- Meta：权限开通后实现 Graph API 分页、429/5xx 退避、cursor 和脱敏原始响应。
- Google：Playwright + 持久 Profile + Xvfb；验证码、登录过期、页面变更进入 `WAITING_MANUAL`。
- 资产：首期只保存官方预览 URL；确认条款、存储周期和对象存储后再下载图片/视频。

## 验收顺序

1. 本地 Mock 提交后得到 202。
2. Java 回调收到 SUCCESS/FAILED/WAITING_MANUAL/TIMEOUT。
3. 同一 runID 重复回调幂等。
4. 单个 Meta query 灰度运行两个日周期。
5. 单个 Google query 先直接验证公开网页；只有遇到验证码或登录挑战时才进入 `WAITING_MANUAL`。
6. 最后才开启 Quartz 定时和多 query 并发。
