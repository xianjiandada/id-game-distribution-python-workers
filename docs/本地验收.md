# 本地联调与验收（复用 Java 测试环境）

本地联调使用 **Java 项目已有的测试数据库、Redis 和其他依赖配置**，不再为 Python Worker 单独创建 MySQL / Redis，也不使用本仓库旧 Docker Compose 的端口和账号覆盖 Java 配置。Python 自己的 SQLite 是任务审计和素材缓存，与 Java 业务库用途不同，仍然保留。

| 验证范围 | 需要启动 |
| --- | --- |
| Python API / Mock | Python Worker |
| 两个平台的直接网页烟测 | Python 环境 + Chromium；不需要启动 API、Java 或数据库服务 |
| Python 直接提交并回调 Java | Worker + Manager，Manager 使用原测试环境；不经过 CMS / Quartz |
| CMS 保存配置 / 立即抓取 / 定时调度完整链路 | CMS + Manager + Quartz + Worker，复用 Java 测试环境 |

## 1. 确认 Java 测试配置和已有表

Java 仓库位于同级目录 `../id-game-distribution-servers`。当前检出的默认 Spring Profile 为 `sharding`、环境标识为 `env=dev`，配置入口：

- Manager：`sf-manager-xstarter/src/main/resources/application.properties` 与 `application-sharding.properties`。
- Quartz：`sf-quartz-xstarter/src/main/resources/application.properties` 与 `application-sharding.properties`。
- 两者素材业务数据源均为 `sdkgamedb0`；Quartz 的 `warehouse` 调度数据源配置为 `sdkgametask`。

这是仓库配置核对结果，不代表已连接或检查实际数据库。IDEA 运行参数、外部配置或环境变量可能覆盖它们；使用 Java 项目现有的测试运行配置，核实最终 Profile 和目标库。数据库连接信息、密码不在本说明中复制，也不改为生产 Profile `shardingprod`。

在 IDEA Database 或现有数据库客户端中，连接 **Java 正在使用的测试业务库**，执行只读检查：

```sql
SELECT DATABASE();
SHOW TABLES LIKE 'advert_creative_query';
SHOW TABLES LIKE 'advert_creative_run';
SHOW TABLES LIKE 'advert_creative_item';
```

完整 CMS 调度验收还需在 Quartz 对应的测试调度库中检查 `ug_job_task` 及素材任务是否已注册。已有表、菜单和任务不重复创建；缺失时才按 Java 仓库 `docs/statistics/素材库/素材库部署与验收.md` 核对对应脚本：

- `creative-schema.sql`：现有业务库内的素材表，不是新建数据库脚本。
- `creative-library-menu.sql`：CMS 素材菜单及后续角色授权。
- `creative-quartz-job.sql`：Quartz 调度库中的素材任务，不在业务库中执行。

`CREATE TABLE IF NOT EXISTS` 不会自动补齐旧表缺失列；结构不一致时先对照最终 schema，不能通过删表重建处理已有测试数据。本次日常验收流程不包含建库、重置或自动导入 SQL。

仓库根目录的 `docker-compose.local.yml` 是早期隔离环境示例，**当前联调不使用**；不需要运行 `docker compose up` 或 `down`，也不删除历史容器 / 数据卷。

## 2. 启动服务（使用 Java 已有运行配置）

| 服务 | IDEA 启动入口 | 默认端口 |
| --- | --- | --- |
| Java Manager | `sf-manager-xstarter/src/main/java/com/ug/server/UGMApplication.java` | `13367` |
| Java Quartz（完整 CMS 链路需要） | `sf-quartz-xstarter/src/main/java/com/ug/server/UGQApplication.java` | `13368` |
| Python Worker | Python 模块 `app`，入口为 `app/__main__.py` | `13371` |

Manager / Quartz 使用各自现有测试配置，保留原 MySQL、Redis、注册中心等设置。不要再复制旧文档中的本地容器数据源覆盖参数。Java 已在运行时直接复用，不重复启动。

如果使用 JAR，在 **Java 仓库根目录** 打包：

```powershell
mvn -pl sf-manager-xstarter,sf-quartz-xstarter -am -DskipTests package
```

分别在两个终端启动，沿用现有测试环境要求的其他参数；仅配置文件内的测试配置足够时，基础命令如下：

```powershell
java -jar sf-manager-xstarter/target/sf-manager-xstarter-1.0.0.jar --spring.profiles.active=sharding
```

```powershell
java -jar sf-quartz-xstarter/target/sf-quartz-xstarter-1.0.0.jar --spring.profiles.active=sharding
```

Python 按 [README 的本地运行 / IDEA 配置](../README.md#本地运行)准备依赖和 Chromium，在 **Python 仓库根目录** 启动：

```powershell
.\.venv\Scripts\python.exe -m app
```

`.env` 中保留 `HOST=127.0.0.1`、`PORT=13371`；手工回调默认使用 `JAVA_CALLBACK_BASE_URL=http://127.0.0.1:13367/internal/creative/runs`。无需把 Java 的 MySQL / Redis 账号复制到 Python。

另开终端检查 Python：

```powershell
Invoke-RestMethod http://127.0.0.1:13371/health
Invoke-RestMethod http://127.0.0.1:13371/workers
```

预期为 `UP`，注册列表含 `mock`、`meta_library`、`google_transparency`。当前 Java 调度代码调用本机 `13371`，开发回调指向本机 `13367`，Manager 触发本机 `13368`；完整本地链路按这三个端口同机运行。任意改端口不能只改 Python `.env`。

## 3. 先验证 Python API（不写 Java 测试库）

以下 Mock 不传 `runID` 和 `callbackUrl`，仅写 Python SQLite：

```powershell
$body = @{ worker = 'mock'; payload = @{ items = @(@{ externalAdID = 'local-check-1'; copyText = 'local check' }) } } | ConvertTo-Json -Depth 8
$job = Invoke-RestMethod http://127.0.0.1:13371/jobs -Method Post -ContentType 'application/json' -Body $body
Invoke-RestMethod "http://127.0.0.1:13371/jobs/$($job.jobID)"
```

提交返回 HTTP `202` 只表示接受任务；重复查询直到状态为 `SUCCESS`。这里没有验证 Java 回调，不能据此判断 Java 素材入库成功。

## 4. 完整 CMS → Quartz → Worker → Manager 验收

1. 启动 CMS，确认它连接当前测试 Manager。入口及前端启动命令见 Java 仓库 `sf-manager-xstarter/README.md`。
2. 确认 Quartz 已注册 `com.ug.server.quartz.jobs.creative.CreativeLibrarySyncJob`。脚本默认任务为暂停状态，定时执行是否启用以测试任务管理实际状态为准。
3. 在 CMS「素材库 / 查询配置」使用真实的测试产品和查询配置，设置每次拉取少量素材，例如 `maxResults=3`。先核对全部启用配置，再保存或点击「立即抓取」。
4. **当前立即抓取会触发全部启用配置的扫描，不只抓取当前一条**；正在 `DISPATCHED` / `RUNNING` 的配置跳过。已成功或失败的其他启用配置也可能再次被派发，因此测试前应确认范围。
5. Quartz 创建 `advert_creative_run` 并提交 Python，记录返回的 `jobID`。Python 结束后直接回调 Manager；在 CMS 运行记录和素材列表检查最终状态及素材。
6. 依次用 Meta 关键词和 Google 广告主名称完成少量抓取，确认查询上下文与产品信息正确。遇到 `WAITING_MANUAL` / `FAILED` 时检查具体错误，不能把“接受触发”当作抓取成功。

本地不再用文档写死的 `runID=2026102601`、`queryID=20001` 等值向共享测试库写入。正常业务 runID 由 Java 生成；`queryID` 必须对应实际配置，编造 ID 可能触发外键错误。

仅测试 Python → Java 回调、不经过 Quartz 时，可按[接口契约](接口契约.md)手工提交带 runID 的任务。当前 Java 回调会在运行记录不存在时创建记录，并非严格拒绝未知 runID；这会写入测试库，应事先约定独立测试 ID 和实际查询上下文，不覆盖已有业务运行。

验收结束后停止本次专门启动的 Quartz 实例或恢复约定的测试调度状态，避免其他启用任务持续执行；共享的既有实例由其维护方管理。

## 5. 验证数据和回调结果

### Python SQLite

默认是 `data/worker.db`；如果设置了 `DATABASE_PATH`，使用实际配置路径。在项目根目录按只读模式查询，文件不存在会报错，不会误建空库：

```powershell
.\.venv\Scripts\python.exe -c "import os,sqlite3; from pathlib import Path; from dotenv import load_dotenv; load_dotenv('.env'); p=Path(os.getenv('DATABASE_PATH','data/worker.db')).resolve(); c=sqlite3.connect(p.as_uri()+'?mode=ro',uri=True); print(c.execute('select jobID,runID,queryID,appID,keyword,status,fetchedCount from worker_job order by acceptedAt desc limit 20').fetchall()); print(c.execute('select media,externalAdID,appID,queryID,keyword from worker_item order by lastSeenAt desc limit 20').fetchall()); c.close()"
```

任务详情接口查询的是内存；重启后旧 `jobID` 会返回 404，SQLite 审计仍保留。当前完成状态先写 SQLite，再发送回调；回调失败添加的 `CALLBACK_FAILED` 不会再次持久化到 SQLite，也没有自动补发队列，所以必须同时检查内存任务详情、Java 日志和 Java 数据库。

### Java 原测试业务库

在已有数据库客户端连接同一个测试业务库，执行只读查询；按实际 `runID` / `queryID` 添加筛选条件定位本次记录：

```sql
SELECT runID, jobID, queryID, appID, searchKeyword, collectionDate,
       status, fetchedCount, newCount, updatedCount, errorCode, errorMessage
FROM advert_creative_run ORDER BY createdAt DESC LIMIT 20;

SELECT media, externalAdID, runID, queryID, appID, searchKeyword,
       advertiserName, firstSeenAt, lastSeenAt
FROM advert_creative_item ORDER BY lastSeenAt DESC LIMIT 20;
```

不再使用 `docker exec creative-worker-mysql ...` 查询另一个隔离库。Python 抓取 `SUCCESS` 不等于 Java 回调成功；Java 未启动时不会在恢复后自动补发，需结合实际运行状态决定重试。Quartz 会跳过仍在 `DISPATCHED` / `RUNNING` 的配置，不能假设再点立即抓取就一定重新派发。

### 素材去重

同一 `media + externalAdID` 多次抓取应仍只有一条最新素材，`lastSeenAt` 更新、`firstSeenAt` 保留。素材上的产品 / 查询上下文会更新为最近一次结果，不保存每个查询各自的素材快照；逐次运行记录另行保留。

当前网页 Worker 的 `newCount` 直接取本次返回条数，`updatedCount` 默认 0，Java 运行记录沿用这两个值。它们尚不代表与数据库比较后的真实新增 / 更新数量；去重验收应看唯一键和实际行数，不能只看这两个计数。

## 6. 只验证两个网页 Worker

不启动 FastAPI、Java 或数据库服务，直接使用同一虚拟环境执行：

```powershell
.\.venv\Scripts\python.exe scripts/live_smoke_test.py --max-results 3
.\.venv\Scripts\python.exe scripts/live_smoke_test.py --meta-keyword "手机壳" --google-advertiser "Supercell Oy" --google-region HK --max-results 2
```

默认查询是 Meta“螺丝”（`ALL`）与 Google `SOFISH TECHNOLOGY PTE. LTD.`（`SG`）。退出码 `0` 表示两平台都返回 `SUCCESS` 且至少一条结果；这是实时外网测试，结果随网络、平台页面和验证状态变化。

脚本直接调用 Worker，不写 Python SQLite、不回调 Java，也不自动加载 `.env`。如需代理或自定义浏览器目录，先在当前终端设置对应环境变量；示例见 [README](../README.md#两个平台快速烟测)。它也不经过宿主的任务超时与并发管理。
